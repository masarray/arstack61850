# M4-P0E3B3 — Exact SCD-to-board roster reconciliation

**Input authority:** firmware-reported `MULTISV SHOW` under the current verified ESP32-P4 boot and session. P0E3B2 requires a full STATUS, selected TXMODE, and all three distinct STREAM rows before announcing `SELECTED`. No previous boot's roster survives reconnection. P0E3B1 separately reads all three actual waveform/quality/CT banks without copying them into Studio's engineering drafts.

**This milestone:** a **read-only, cached** `MATCHED / MISMATCH / NO SCD / NOT VERIFIED` status compares the live selected board roster against the one canonical ARM3 binary previously compiled by `SclProfileModel`. The existing `M4MultiSvUploadTransaction` ARM3 decoder and **same** `validateStream` function used by deploy verify the original firmware STREAM lines. The 64-bit whole-record hash must match, and each slot's svID, destination MAC, APPID, VLAN present/VID/PCP, 4000-fps rate, counter wrap, noASDU and confRev must match. All three slots are required, with no duplicate or missing row. The status is invalidated and recomputed on boot/roster/SCD change; the expensive decoder is not run on 250-us publisher timing or every QML frame.

**Operator behavior:** a compact label appears for the selected firmware roster even when the engineer has not opened the three-MU draft pages. Diagnostics include selected mode, hash, and exact SCD match result. A missing/invalid SCD displays `NO SCD`; an unrelated SCD or altered MAC/VLAN/APPID displays `MISMATCH`. Neither option modifies board TX, changes active waveform banks, writes GUI drafts, or starts/stops publishing.

**Safety boundary:** MATCHED is **only a roster identity comparison**; it is **not** proof that three MU banks have the desired generation/scenarios, three TX enable gates are ready, group START is safe, PTP is qualified, or that 3×4,000 fps has been measured. M4 group START stays blocked. Next P0E3C is board-owned group START/STOP readback gated by authoritative runtime proof; P0F requires independent physical Ethernet capture.

**CI economy:** extend the existing `arstack_m4_upload_harness` with positive and negative SCD-to-firmware stream comparisons (MAC, APPID, svID, VLAN, rate, wrap, confRev, missing/duplicate roster, whole-record hash, binary CRC), keep existing Windows/Linux Qt, S8 and ESP32-P4 workflows and matrices unchanged.
